### 1. Encoding Kya Hoti Hai? (What is it?)
Encoding ek aisi **transformation (badlaav) process** hai jisme data ko ek format ya standard se dusre format mein convert kiya jata hai taake alag-alag systems, protocols, ya browsers usko bina kisi error ke samajh sakein aur process kar sakein.
 * **Sabse Badi Baat:** Encoding mein **koi security, privacy ya encryption nahi hoti**. Isme koi secret key (chabi) nahi lagti. Jo algorithm data ko encode karta hai, wahi public algorithm usko foran decode bhi kar sakta hai. Iska maqsad data ko chupana bilkul nahi hai, balki **data ko safely represent karna** hai taake system data ki corruption se bach sake.
### 2. Yeh Kis Liye Use Hoti Hai? (Purpose)
 * **Data Transport:** Internet par jab hum data bhejte hain (jaise browser se server tak), toh kuch special characters (jaise space, ?, /, &) network mein ya URL mein masle paida kar sakte hain. Encoding un characters ko safe format mein badal deti hai.
 * **Compatibility:** Kuch systems sirf text data samajhte hain (jaise email ya JSON/XML files), toh binary data (jaise images ya files) ko text format mein badalne ke liye encoding use hoti hai.
### 3. Encoding ki Mukhtalif Qismein (Common Types)
Web applications mein aapko aam taur par yeh encoding types dekhne ko milengi:
 1. **Base64 Encoding:** Yeh binary data (jaise images, files, ya tokens) ko ASCII text characters mein badal deti hai. Isme aakhir mein aksar = ya == sign aata hai. *(Misal: aGVsbG8= matlab "hello").*
 2. **URL Encoding (Percent Encoding):** URLs mein space ya special characters ko handle karne ke liye use hoti hai. Space ki jagah %20 ya + lag jata hai.
 3. **Hexadecimal Encoding (Hex):** Har character ko uske hexadecimal number mein badal diya jata hai (jaise 41 matlab capital A).
 4. **HTML Entity Encoding:** Web pages par HTML tags ko safe rakhne ke liye use hota hai taake browser unhein code samajhne ke bajaye text samjhe (jaise < ki jagah &lt; likhna).
### 4. Hacker ke liye yeh kaise beneficial sabit ho sakti hai? (Hacker's Perspective)
Ek cyber security attacker ya pentester encoding ko kai tareeqon se apne fayde ke liye istemaal karta hai:
 * **WAF Bypass (Web Application Firewall Bypassing):** Bahut si websites ya WAFs par filters lage hote hain jo dangerous payloads (jaise XSS ya SQL Injection scripts) ko pakad kar block kar dete hain. Hacker apnay payload ko **URL encode**, **Hex encode**, ya **Double encode** karke bhejta hai taake WAF usko pehchan na sake, lekin server par jaakar jab woh decode hota hai, toh execute ho jata hai.
 * **Obfuscation (Chhupan-Chhupai):** Scripts ya malicious payloads ke andar ke commands ko chhupane ke liye Base64 encoding ka istemaal kiya jata hai taake agar koi normal banda code ko dekhe toh foran samajh na paye ke andar kya chal raha hai.
 * **Data Exfiltration:** Agar kisi system se chori kiya gaya data wapas bhejna ho, toh hacker us data ko Base64 encode karke HTTP requests ke zariye aasani se bahar nikal leta hai taake network monitoring tools ko foran shak na ho.
### 5. Cyber Security Expert ko isko samajhna kyun zaroori hai? (Importance for Pentester)
 * **Traffic Analysis:** Jab aap Burp Suite mein web traffic intercept karte hain, toh kai requests aur parameters Base64 ya URL encoded format mein nazar aate hain. Agar apko encoding ki pehchan nahi hogi, toh aapko samajh hi nahi aayega ke request ke andar asal data kya ja raha hai.
 * **Input Validation Testing:** Yeh check karne ke liye ke application encoded inputs ko kaisay handle karti hai aur kahin decoding ke baad koi vulnerability toh trigger nahi ho rahi, expert ko iska pata hona laazim hai.
### 6. Website mein yeh kahan kahan lagti hai?
 * **URL Parameters:** Browser URL bar mein agar aap space ya special symbols dalein, toh website usko khud-ba-خود URL encode kar deti hai.
 * **Images in CSS/HTML:** Bahut si websites images ko alag se load karne ke bajaye unka Base64 code seedha HTML/CSS ke andar embed kar deti hain (jaise data:image/png;base64,...).
 * **Forms & API Requests:** Jab aap form submit karte hain ya JavaScript ke zariye APIs par data bhejte hain (application/x-www-form-urlencoded), toh data encode hokar hi travel karta hai.
### 7. Burp Suite ka Decoder Tool Kis Liye Hota Hai?
**Burp Suite Decoder** pentester ka ek behtareen built-in utility tool hai. Iska kaam hi data ko encode, decode, aur hash karna hai.
 * **Kaise Kaam Karta Hai?**
   Agar aapko Burp Suite ke Proxy ya Repeater mein koi aisi string milti hai jo Base64 encoded hai ya URL encoded hai aur aapko samajh nahi aa rahi, toh aap usko copy karke **Decoder** tab mein dalte hain. Wahan aap ek hi click mein usko **Decode as Base64** ya **URL** kar lete hain taake woh aapko asal plaintext form mein dikh jaye.
 * Isme aap ulta kaam bhi kar sakte hain—koi naya payload likh kar usko foran Base64 ya Hex mein encode karke target par attack ke liye use kar sakte hain.

### 1. Kuch systems sirf text data kyun samajhte hain? Aur Images/Files text mein kaise convert hoti hain?
**Kyun samajhte hain sirf text?**
Internet ki shuruat mein jo protocols banaye gaye the (jaise Email ke liye SMTP, ya Web ke liye HTTP, JSON, XML), unhein design is tarah kiya gaya tha ke woh sirf **plain text (ASCII characters)** ko behtar tareeqe se handle kar sakein. Agar aap raw binary data (yani 0 aur 1 ki shakal mein direct bytes) email ya web requests ke zariye bhejne ki koshish karein, toh raste mein network routers ya systems un bytes ko galat samajh kar modify ya corrupt kar sakte hain (misal ke taur par, agar binary data mein kahin NULL byte \x00 aa jaye, toh kuch systems usko "file ya message ka aakhri hissa" samajh kar baaki data drop kar dete hain).
**Images ya Files text mein kaise convert hoti hain? (Base64 ka Jaadu):**
Iska sabse bada example **Base64 Encoding** hai.
 * Jab aapke paas koi image (misal ke tor par image.png) hoti hai, toh computer ki nazar mein woh sirf binary data (0s aur 1s / bytes) hoti hai.
 * Base64 algorithm kya karta hai? Woh us binary data ko uthata hai aur **6-bits ke tukron** mein baant deta hai.
 * Phir har 6-bit ke tukre ko English alphabet (A-Z, a-z), numbers (0-9), aur do symbols (+, /) mein se kisi ek character se replace kar deta hai.
 * Is tarah poori image ek lambi **text string** mein badal jati hai (jiske aakhir mein = ya == laga hota hai).
**Wapas decode hone par image kaise ban jati hai?**
Jab browser ya system us Base64 text string ko receive karta hai, toh woh usko ulta process (decode) karta hai:
 1. Har text character ko wapas 6-bit binary mein badalta hai.
 2. Un 6-bit tukron ko wapas standard 8-bit bytes mein jorta hai.
 3. Jab saare bytes apni asal tarteeb (sequence) mein wapas aate hain, toh computer usko wapas wahi original image file ya PDF ki shakal mein render kar deta hai. Matlab data ka ek bit bhi zaya ya change nahi hota, bas uska *representation* badal jata hai.
### 2. Hexadecimal (Hex) conversion kaise hoti hai? (A-Z aur numbers ka chakkar)
Aapne bilkul theek socha, Hexadecimal mein har character ya number ka ek mukhtasir code hota hai.
 * **Base-16 System:** Normal counting hum 10 digits wali use karte hain (0 se 9 tak). Lekin Hexadecimal mein 16 values hoti hain: **0 se 9 tak** digits, aur **A se F tak** letters (jahan A=10, B=11, C=12, D=13, E=14, F=15).
 * **Kaise convert hota hai?** Computer mein har letter ya number ka ek underlying ASCII ya Unicode number hota hai.
   * Misal ke tor par, capital letter **'A'** ka decimal number **65** hota hai. Jab isko Hex mein badalte hain, toh yeh **41** ban jata hai.
   * Chhota letter **'a'** ka decimal 97 hota hai, jo Hex mein **61** banta hai.
   * Koi bhi number ya special character ho, uska apna ek Hex code hota hai (jaise space ka Hex code **20** hota hai). Burp Suite ya pentesting mein hum aksar dekhte hain ke payloads Hex format (\x41\x42\x43) mein likhe hote hain taake security filters ko dhoka diya ja sake.
### 3. WAFs ko confuse karne ke liye kya sirf yeh 3 formats use hote hain? (URL, Hex, Double Encode)
**Haan, bilkul!** WAF (Web Application Firewall) ko bypass karne ke liye yeh sabse purane aur powerful tareeqe hain, aur inhi ke ird-gird saare encoding bypasses ghoomte hain:
 1. **URL Encoding / Percent Encoding:** Misal ke tor par agar aap <script> tag bhej rahe hain, toh WAF usko foran pakad lega. Lekin agar aap usko URL encode karke %3Cscript%3E bhej dein, toh WAF ka signature filter confuse ho sakta hai, aur jab server par jaakar woh decode hoga, toh script execute ho jayegi.
 2. **Hex Encoding:** Kuch WAFs URL encoding ko toh pakad lete hain, lekin agar aap pure payload ko Hex format mein bhej dein (jaise SQL injection ya XSS string ka Hex equivalent), toh WAF usko normal text samajh kar jane deta hai, jabke backend application usko process ya decode kar leti hai.
 3. **Double Encoding (Sabse Khatarnak):** Isme hacker ek hi payload ko **do baar** encode kar deta hai (misal ke tor par pehle URL encode kiya, phir jo result aaya usko dobara URL encode kar diya).
   * *Kaise kaam karta hai?* Jab request WAF se guzarti hai, toh WAF sirf ek baar decode karta hai, wahan usko lagta hai ke yeh toh sirf aik normal URL encoded string hai (koi khatarnak script nahi). Lekin jab request aage web server ya application tak pahonchti hai, toh application usko **doosri baar bhi decode** kar leti hai, aur woh hidden malicious payload asli shakal mein bahar aakar execution shuru kar deta hai!
**Iske ilawa aur kya hota hai?**
In teen ke ilawa attackers **Unicode Encoding**, **HTML Entity Encoding**, aur **Null Byte Injection** ka bhi istemaal karte hain WAFs ko bypass karne ke liye, lekin base yahi sab encoding techniques hoti hain jo aapne abhi samjhi hain.
