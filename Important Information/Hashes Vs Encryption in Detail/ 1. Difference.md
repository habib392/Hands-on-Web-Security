
### 1. Encryption aur Hashing mein Bunyadi Farq
| Feature | Encryption | Hashing |
|---|---|---|
| **Nature** | **Two-Way (Reversible):** Yeh do-tarafa process hai. Data ko encode kiya jata hai, aur phir key (chabi) ki madad se wapas original form (plaintext) mein decrypt kiya ja sakta hai. | **One-Way (Irreversible):** Yeh ek-tarafa process hai. Data ko ek fixed-length string (hash) mein badal diya jata hai. Hash se wapas original data ko hasil nahi kiya ja sakta. |
| **Maqsad (Purpose)** | Secure communication aur data ko safe transfer ya store karna taake sirf authorized banda hi key se parh sake. | Data ki integrity (sachai/durusthi) check karna aur passwords ko safely store karna. |
| **Chabi (Key)** | Isme **Encryption Key** (aur asymmetric mein Public/Private Key) ka istemaal hota hai. | Isme kisi bhi tarah ki key ka istemaal nahi hota, balki ek cryptographic algorithm (mathematical formula) lagta hai. |
### 2. Kya dono sirf password ko secure karne ke liye hote hain?
**Nahi, bilkul nahi!**
 * **Encryption** ka maqsad password secure karna nahi hota, balki poori file, message, ya network traffic ko secure rakhna hota hai taake agar beech mein koi data chura bhi le (Man-in-the-Middle attack), toh woh usko parh na sake jab tak ke uske paas key na ho.
 * **Hashing** ka istemaal passwords ko database mein secure rakhne ke liye hota hai (kyunki website ko khud bhi aapka asal password pata hone ki zaroorat nahi hoti, sirf hash match karna hota hai). Iske ilawa files ki **Integrity Check** (jaise Kali Linux ya koi software download karte waqt SHA256 checksum match karna) ke liye bhi hashing use hoti hai.
### 3. Hackers ke liye kis ko guess ya crack karna easy hai?
 * **Hashing ko Crack karna:** Kyunki hashing one-way hoti hai, isko mathematically "decrypt" nahi kiya ja sakta. Lekin hackers iske liye **Brute-Force Attack** ya **Dictionary Attack** ka istemaal karte hain. Agar password weak ho ya hashing algorithm purana ho (jaise MD5 ya SHA-1 bina salt ke), toh hacker tools ki madad se millions of combinations try karke usko match kar leta hai (crack kar leta hai). Lekin agar modern hashing algorithms (jaise **bcrypt** ya **Argon2**) strong salt ke sath use hon, toh unhein crack karna almost namumkin ho jata hai.
 * **Encryption ko Crack karna:** Agar encryption algorithm weak ho (jaise purana DES ya RC4) ya key bohot choti ho, toh use todna aasan hota hai. Lekin strong encryption (jaise **AES-256**) ko bina key ke brute-force karna supercomputers ke liye bhi arbon saal le sakta hai. Hacker encryption tabhi crack kar pata hai jab use **Private Key** mil jaye, server misconfiguration ho, ya weak key management ho.
### 4. Inko Implement aur Decrypt/Crack karne ke Tools
#### **Encryption ke Tools & Libraries:**
 * **OpenSSL:** Command-line tool jo files aur text ko encrypt/decrypt karne ke liye use hota hai.
 * **GnuPG (GPG):** Files aur communications ko secure banane ke liye.
 * **CyberChef:** Web-based tool jo encryption, encoding, aur hashing sab kuch test karne ke liye best hai.
 * **Python Cryptography Library (cryptography / AES):** Programming mein encryption implement karne ke liye.
#### **Hashing aur Crack karne ke Tools (Pentesting Tools):**
 * **Hashcat:** Duniya ka sabse taqatwar password recovery aur hash cracking tool (GPU-accelerated).
 * **John the Ripper:** Ek aur mashhoor password cracking tool jo various hashes ko crack karta hai.
 * **CrackStation:** Online database jo pre-calculated hashes (rainbow tables) ko lookup karne ke kaam aata hai.
 * **Programming Languages:** Python mein hashlib ya PHP mein password_hash() hashing implement karne ke liye.
### 5. Website mein kahan Encryption hoti hai aur kahan Hashing?
Ek typical web application mein inka istemaal is tarah hota hai:
 * **Kahan Encryption hoti hai?**
   1. **Data in Transit (HTTPS / TLS):** Jab aap browser se kisi website par login karte hain ya credit card details dalte hain, toh client aur server ke darmiyan poora traffic encrypt hota hai (SSL/TLS certificate ke zariye).
   2. **Sensitive Database Fields:** Kuch highly confidential data (jaise user ke bank account numbers ya personal notes) database mein encrypt karke store kiye jate hain taake agar database leak bhi ho jaye toh company unhein decrypt karke dekh sake.
 * **Kahan Hashing hoti hai?**
   1. **User Authentication (Passwords):** Jab user account banata hai, toh website password ko database mein plaintext mein save nahi karti, balki usko hash (jaise bcrypt ya Argon2) mein convert karke save karti hai. Login ke waqt user jo password dalta hai, website uska dobara hash banakar database wale hash se match karti hai.
   2. **File Integrity:** Website par agar koi file ya update download ke liye rakhi hai, toh uska SHA-256 hash diya jata hai taake user check kar sake ke file ke sath koi cheeni (tampering) toh nahi ki gayi.
