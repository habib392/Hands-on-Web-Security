### **1. Bcrypt se Password Hash (Encrypt) Kaise aur Kis Jagah Hota Hai?**
Sabse pehle yeh samajhna zaroori hai ke passwords ko kabhi bhi database mein **Plain Text** (jaise password123) save nahi kiya jata, kyunki agar database hack ho jaye toh saare users ke passwords leak ho jayenge. Iske liye **Bcrypt** use hota hai.
 * **Kis jagah hota hai? (Backend / Server side):**
   Jab user apni website ya app par sign up ya register karta hai aur apna password enter karta hai, toh woh password request ki shakal mein server (Backend) par jata hai. Server database mein save karne se theek pehle Bcrypt library ko call karta hai.
 * **Kaise hota hai? (Hashing Process):**
   Bcrypt password ko "Hash" karta hai, "Encrypt" nahi. Farq yeh hai ke encryption two-way hoti hai (decrypt ho sakti hai), lekin hashing one-way hoti hai (hash ko wapas plain text password mein convert nahi kiya ja sakta).
   * **Salt add hota hai:** Bcrypt password ke sath ek random string (salt) milata hai taake agar do users ka password "123456" bhi ho, toh unka hash bilkul mukhtalif bane.
   * **Hasting / Slowing down:** Bcrypt aik "Work Factor" (rounds) use karta hai jo password ko bar bar compute karke itna slow kar deta hai ke koi brute-force attack karke asani se guess na kar sake.
   * **Database mein save:** Jab Bcrypt password ko ek lambi secure string (jaise $2b$10$...) mein badal deta hai, toh server us hash ko database ke users table mein save kar leta hai. Login ke waqt bhi yahi hota hai; user jo password dalta hai, Bcrypt usko dobara hash karke database wale hash se match karta hai.
### **2. HTTP Headers Konsy Hoty Hain Jinhy Security Libraries (jaise Helmet.js) Secure Krti Hain?**
Jab browser kisi server se website load karta hai, toh server browser ko kuch HTTP Headers bhejta hai. Agar yeh headers theek tarah configure na hon, toh hackers mukhtalif attacks (jaise Clickjacking, XSS, MIME sniffing) kar sakte hain. Node.js mein **Helmet.js** library inhi headers ko automatically secure karti hai.
 * **1. Content Security Policy (CSP):**
   Yeh header browser ko batata hai ke website par sirf kahan kahan se scripts (JavaScript, CSS, Images) load ho sakti hain. Isse XSS attacks rokne mein boht madad milti hai.
 * **2. X-Frame-Options:**
   Yeh header batata hai ke kya aapki website ko kisi doosri website par <iframe> ke andar khola ja sakta hai ya nahi. Isko DENY ya SAMEORIGIN set karke hacker aapki site ko invisible frame mein rakh kar clickjacking attack nahi kar sakte.
 * **3. X-Content-Type-Options:**
   Iska main header X-Content-Type-Options: nosniff hota hai. Yeh browser ko zabardasti rokta hai ke woh file ke MIME type (jaise image ya stylesheet) ko khud-ba-khud guess (sniff) na kare, balkay wahi maane jo server ne bataya hai. Isse malicious file upload attacks kam hote hain.
 * **4. Strict-Transport-Security (HSTS):**
   Yeh header browser ko force karta hai ke woh hamesha secure connection (HTTPS) par hi site load kare, agar koi HTTP likhe ga toh browser khud usko HTTPS mein badal dega (Man-in-the-Middle attacks se bachne ke liye).
 * **5. X-XSS-Protection:**
   Purane browsers mein yeh header XSS filter ko on rakhta hai (halanki modern browsers mein CSP zyada behtar kaam karta hai).
### **3. XSS ko Roknay Wala DOMPurify Kya Hai?**
 * **DOMPurify kya hai?**
   DOMPurify ek JavaScript library hai jo Client-side (browser mein) ya Server-side (Node.js mein) par chal kar untrusted HTML/Markdown ko "sanitize" (saaf) karti hai.
 * **Yeh kaise kaam karta hai?**
   Aksar web applications mein aisi jagah hoti hain jahan users apna content khud likh sakte hain (jaise comments box, forum posts, ya profile bio). Agar koi user comment mein malicious JavaScript code daal de (jaise <script>alert('XSS')</script> ya <img src=x onerror=alert(1)>), aur website usko baghair saaf kiye direct page par render (DOM mein insert) kar de, toh doosre user ke browser mein woh script chal jayegi (Stored XSS).
 * **DOMPurify ka role:**
   Jab user koi aisi HTML string input karta hai, toh DOMPurify us poori string ko parse karta hai, saare dangerous tags (<script>, <object>, <embed>) aur dangerous attributes (onerror, onload, javascript:) ko dhoond kar nikal deta hai (strip kar deta hai), aur sirf safe HTML (jaise <b>, <i>, <a>) ko chorta hai. Is tarah browser safe rehta hai aur XSS execute nahi hota.
